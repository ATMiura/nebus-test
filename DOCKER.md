# Запуск через Docker

Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/). Дождитесь запуска Docker Engine. После установки откройте новый терминал, чтобы команда docker стала доступна. Node.js отдельно устанавливать не нужно.

Если приложение уже запущено через `npm run dev`, остановите его сочетанием Ctrl+C: порт 3000 должен быть свободен.

Из папки проекта выполните:

```sh
docker compose up --build
```

При первом запуске Docker скачает образ Node.js, установит зависимости и соберёт приложение. После запуска откройте <http://localhost:3000>.

Чтобы остановить приложение, нажмите Ctrl+C. Остановить приложение и удалить контейнер и созданную Compose сеть:

```sh
docker compose down
```

После изменения исходников снова выполните `docker compose up --build`.

Эта команда пересобирает образ и пересоздаёт контейнер при изменении образа. Простой запуск старого контейнера кнопкой Start в Docker Desktop не обновляет его сборку.

Если используется отдельная команда `docker-compose`, команды те же: `docker-compose up --build` и `docker-compose down`. Запрошенный в задании `docker-compose up` тоже собирает образ при первом запуске.

Заметки и черновики хранятся в localStorage браузера. Они остаются после остановки контейнера при использовании того же браузера и адреса. В другом браузере, профиле или на другом порту будет своё хранилище.

`Dockerfile` описывает установку зависимостей, сборку и запуск приложения. В финальный образ попадает только готовая папка `.output`.

`docker-compose.yaml` задаёт сборку приложения и доступ к нему на порту 3000.

`.dockerignore` исключает локальные зависимости, предыдущие сборки и служебные файлы из сборки образа.
